# 学习任务板

一个本地运行的任务管理工具。记录任务名称、负责人、截止日期和状态，支持筛选与进度统计。

**零第三方依赖**——只用 Python 标准库，`python app.py` 即可启动，不需要 `pip install` 任何东西。

## 特性

- **增删改查**：添加任务、编辑全部字段、删除（带确认）、按负责人/状态/关键词组合筛选
- **进度统计**：顶部实时显示总数、已完成、未完成和完成率，统计口径始终是全部任务，不受筛选影响
- **严格校验**：日期必须真实存在（`2026-02-30` 会被拒绝），状态限定三值，任何一项不合格都不落盘
- **数据安全**：写入采用临时文件 + 原子替换，进程被杀不会留下半个 JSON
- **CSRF 防护**：每次启动生成一次性令牌，所有 POST 请求都要比对
- **仅本机访问**：绑定 `127.0.0.1`，不对局域网或公网开放

## 快速开始

需要 Python 3.11 或以上。

```bash
cd starter
python check_env.py     # 可选：检查版本与目录写入权限
python app.py
```

终端出现下面这行后，浏览器打开 <http://127.0.0.1:8765>：

```
浏览器打开 http://127.0.0.1:8765 。终端按Ctrl+C停止。
```

端口被占用时换一个：

```bash
python app.py --port 8766
```

按 `Ctrl+C` 停止。**不要双击 `app.py` 启动**，也不要关闭终端——关掉终端等于停止服务。

## 使用

| 操作 | 说明 |
|---|---|
| 添加任务 | 填写名称、负责人、截止日期、状态和说明，点「添加任务」 |
| 编辑 / 改状态 | 任务行点「编辑 / 状态」，改完点「保存修改」 |
| 删除 | 点「删除」后浏览器弹确认框，点「确定」才真正删除 |
| 查询 | 按负责人、状态、关键词筛选。负责人和状态按完整值匹配，关键词在任务名称或说明中查找，多个条件需同时满足 |
| 清除筛选 | 点「清除筛选」恢复全部，或直接访问 `/` |

输入规则：

- 任务名称、负责人去掉首尾空格后不能为空
- 截止日期必须是 `YYYY-MM-DD` 格式，且是真实存在的日期
- 状态只能是「待开始」「进行中」「已完成」之一

校验失败时页面会提示原因，**并把刚填的内容带回表单**，不用重新输入。

## 项目结构

```
starter/
├── app.py              # 启动入口：HTTP 服务、路由、会话令牌
├── service.py          # 业务逻辑：校验、增删改、筛选、统计（纯函数）
├── storage.py          # 持久化：原子读写 data/tasks.json
├── web.py              # 视图：渲染 HTML 页面
├── config.py           # 页面标题与说明文字
├── check_env.py        # 环境自检：Python 版本、目录写入权限
├── data/
│   ├── tasks.json      # 运行时数据（首次添加任务时自动创建，不提交）
│   └── tasks_demo.json # 10 条示例数据，用于演示
├── test_edit.py        # 编辑校验与删除的测试
├── test_filter.py      # 筛选功能的测试
└── test_stats.py       # 进度统计的测试
```

分层很直接：`app.py` 只负责 HTTP 收发，`service.py` 不碰文件系统，`storage.py` 只管读写。这样业务逻辑可以脱离服务器直接单元测试。

## 数据存储与备份

数据保存在 `data/tasks.json`，路径由 `storage.py` 自身位置推导，整个文件夹移动到别处仍可用。

**备份**：停止程序后，把 `data/tasks.json` 复制一份，例如 `tasks_backup_20261109.json`。

**恢复**：停止程序，把备份复制回 `data/tasks.json` 覆盖，重新启动。

**演示数据**：`data/tasks_demo.json` 含 10 条示例任务（待开始 4、进行中 3、已完成 3）。演示前先备份正式数据，再把 `tasks_demo.json` 复制成 `tasks.json`。

如果 `tasks.json` 损坏，程序会报出具体行号并停止启动，**不会自动覆盖原文件**——你可以先备份再修复。

## 实现要点

几个值得说明的取舍：

**为什么不用 Flask。** 整个项目只有四个路由和十几条业务规则，标准库的 `http.server` 足够，换来的是「克隆下来就能跑」——没有任何环境准备成本。

**为什么用字符串拼 HTML。** `web.py` 用 f-string 直接拼，所有用户输入都过 `html.escape(quote=True)`。代价是没有模板复用，好处是没有模板注入面、没有额外依赖。对单页面应用来说这个权衡是划算的。

**原子写入。** `storage.py` 先写同目录的临时文件，`flush` + `os.fsync` 确保落盘，再用 `os.replace` 原子替换。中途断电最多丢掉这次修改，不会产生半个损坏的 JSON。

**防重复提交。** 每次启动用 `secrets.token_urlsafe` 生成令牌，嵌入表单，POST 时用 `secrets.compare_digest` 比对（恒定时间比较）。重启后旧令牌失效，页面会提示「页面已过期，请刷新后重试」。

**状态更新用不可变副本。** `service.py` 的每个函数都 `deepcopy` 出新列表再改，任何一步校验失败都不会污染原数据。

## 已知限制

- 单用户、单进程，没有登录、权限和并发保护，不适合公网部署
- 数据存在单个 JSON 文件，任务量大时全量读写，没有索引
- 只在 Windows 11 + Python 3.13 实测过；Linux 和 macOS 理论上可用，未实机验证
- 没有分页，几千条任务以上需要考虑虚拟滚动或后端分页

## 环境

- Python 3.11+
- 浏览器：Chrome / Edge 等现代浏览器
